# 데스 카운트

15인 모바일 눈치 게임. 한 사람이 누른 뒤 서버 기준 200ms 이하에 다른 사람이 누르면 해당 숫자에서 크래시가 발생하고 함께 누른 사람들이 벌칙자가 된다. 1.8초 뒤 원래 폭탄 숫자를 공개하고, 그 숫자를 이미 누른 사람도 벌칙에 추가한다. 폭탄 숫자를 단독으로 눌렀을 때는 게임을 계속한다.

## 플레이

- 닉네임 → 방 만들기 → 초대 링크/6자리 코드 공유 → 15명 입장 → 방장 시작.
- 라운드마다 무작위 3명에게만 참인 폭탄 힌트를 준다.
- 숫자별 입력자를 기록한다. 충돌 후 원래 폭탄이 이미 지나갔다면 해당 입력자를 추가 벌칙자로 지정한다. 폭탄에 도달하지 않았다면 추가 벌칙자는 없다.
- 충돌 없이 15까지 가면 종료하고 폭탄 벌칙만 공개한다. 같은 사람이 충돌·폭탄 모두에 해당해도 벌칙은 한 번이다.
- 혼자 연습은 14명의 서버 봇과 시작한다. 실제 사람과의 방과 구분된다.
- 한 사람이 여러 번 누를 수 있다. 단독 성공한 공통 숫자 n마다 n×10점 획득: 1은 +10, 2는 +20, 3은 +30점. 한 사람이 모두 성공했다면 합계 60점이다. 200ms 판정 전에는 지급하지 않으며 충돌 입력은 0점이다.
- 폭탄 입력자의 이전 라운드까지 포함한 누적 점수는 0으로 초기화한다. 충돌만 한 사람은 그 입력의 보상만 없고 이전 점수는 유지한다.
- 개인전은 연속 성공 제한이 없다. 팀전은 자동 균등 배정된 3팀×5명으로 팀원 점수를 합산한다.
- 팀전에서 같은 사람이 두 숫자를 연속 성공하면 다음 버튼을 잠근다. 다른 참가자의 단독 성공이 확정되어야 잠금이 해제된다. 같은 팀/다른 팀 모두 해제 가능하다. SQL도 이 조건을 검사하므로 버튼 우회·지연 입력으로 3연속 성공할 수 없다.
- 3라운드를 모두 마친 후 최고 개인 점수 또는 최고 팀 합계로 우승. 동점은 공동 우승, 전원 0점이면 무승부. 새 라운드에는 연속 기록만 초기화하고 점수는 유지하며, 새 게임은 점수도 초기화한다.
- 정해진 입력 제한 시간은 없다. 쿨타임은 계속 진행하는 단독 입력 확정 뒤 500~1500ms이며 남은 시간을 화면에 예고하지 않는다.

## 서버 및 시간

Cloudflare Worker + D1. 모든 입장과 판정은 서버에서 수행한다. `death_rooms` 한 행을 룸 단위 권위 상태로 사용한다. SQLite 설명 기능이 없으므로 테이블과 각 컬럼 description은 `db/schema.ts`, 마이그레이션 주석, 아래 데이터 사전에 함께 기록한다.

입력의 권위 수신 지점은 D1 primary의 직렬 UPDATE 실행 시각이다. 첫 유효 쓰기가 `[t0,t0+200ms]` 창을 연다. 조건부 UPDATE 한 문장으로 참가자 검증, 중복 제거, 창 개설과 입력 추가를 수행한다. 기기 시각·HTTP 진입 시각을 소급 적용하지 않는다. 원안 GDD의 단일 서버 단조시계 큐를 분산 호스팅의 DB 직렬 시계로 구체화한 구현이다.

확정은 마감 이후 서버 동기화 요청에서 수행하며 버전 CAS로 한 번만 적용한다. 클라이언트는 응답 완료 후 140ms 간격으로 상태를 요청한다(로비/결과 650ms, 백그라운드 1200ms). 원안의 WebSocket 기준안은 배포 환경에 맞춰 짧은 HTTP 폴링으로 변경했다. 체감 결과 지연은 200ms 창 + 폴링 대기 + 네트워크·DB 처리 시간이다. 모든 클라이언트가 닫히면 판정 저장은 다음 요청까지 지연되지만 마감 이후 입력은 여전히 거절한다. 전용 실시간 서버의 푸시 성능을 보장하지 않는다.

개인 토큰은 탭의 sessionStorage에 저장하고 서버에는 SHA-256 해시만 저장한다. 이것은 재접속 자격이며 게임 상태의 원본은 DB다. 게임 중에는 폭탄·타인 힌트·자격 해시·입력자 집합을 공개하지 않는다. 종료 직후에는 충돌자만 보여주고, 실제 종료 쓰기 시각에서 1800ms 이후 원래 폭탄·해당 입력자·숫자별 기록·최종 점수를 공개한다. 클라이언트 시계를 조작해도 조기 공개되지 않는다. 결과 저장은 한 번만 수행하며, 공개 전 공개 API의 개인 점수와 팀 합계는 폭탄 초기화 전의 값으로 유지하여 폭탄 담당자를 미리 누설하지 않는다. 다음 판 진행은 종료 후 4000ms부터 허용한다.

새로고침은 같은 참가자로 복구된다. 봇은 폭탄·타인 힌트를 참조하지 않고 독립 난수 시각으로 입력하며 팀전 연속 제한을 동일하게 적용한다. 이전 규칙의 승수는 점수로 환산하지 않으므로 v3 업데이트 후 첫 동기화에서 참가자를 유지한 채 0점 개인전 로비로 초기화한다.

룸은 생성 후 2시간 유효하다. 진행 중 참가자 교체·호스트 자동 위임은 제공하지 않는다. 호스트는 같은 탭에서 새로고침해 복구할 수 있다. 시작 전 방장이 명시적으로 나가면 다음 사람에게 위임한다. 만료 행 자동 삭제 정책은 별도 운영 과제다.

## 데이터 사전

| 테이블/컬럼 | description |
|---|---|
| death_rooms | 룸별 권위 게임 상태와 비밀 데이터 |
| code | 기본 키인 6자리 공유 방 코드 |
| state | 참가자 자격 해시·함정·힌트·입력 창·누적 점수·게임 모드·팀·연속 성공 기록의 서버 전용 JSON |
| revision | CAS 경쟁 갱신 및 클라이언트 역순 응답 차단 버전 |
| expires | 룸 만료 Unix 밀리초 |

## 개발 및 검증

프로젝트 폴더에서 `pnpm install --ignore-workspace` 후 `pnpm dev --port 5174` 실행.
로컬 DB는 `pnpm exec wrangler d1 execute site-creator-d1 --local --config wrangler.local.json --file drizzle/0000_brown_vermin.sql`로 생성한다(새 DB에서 한 번).

- `node --test tests/game.test.mjs`: 실제 SQLite SQL, 가상 DB 시계, API 핸들러의 경쟁 조건과 규칙 검증.
- `node tests/http.test.mjs`: 실행 중인 서버의 15개 독립 참가 자격, 동시 입력, 결과 일치, 재접속, 봇 진행 검증. `GAME_URL`로 테스트 대상 지정 가능.
- `node tests/team-http.test.mjs`: 로그인 없이 15명 입장, 3팀 배정, 1·2 성공 후 차단, 타인 3 성공 후 4 재활성화와 70점 누적 검증.
- `pnpm exec tsc --noEmit`, `pnpm build`: 타입 및 Cloudflare Worker 배포 빌드.

기획·아트·QA·사운드 독립 에이전트 검토를 반영했다. 효과음은 외부 음원 없이 WebAudio로 합성한다. 음소거와 동작 줄이기 설정을 존중한다.
