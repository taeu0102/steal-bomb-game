# 인터랙티브 동화 플레이어 UX·QA 제품 사양

## 1. 문서 목적

이 문서는 부모와 아이가 함께 읽고 선택하는 인터랙티브 동화 웹 게임의 공통 UX, 접근성, 진행 저장, 플레이어 상태 모델, QA 범위와 출시 수용 기준을 정의한다. 첫 콘텐츠는 「흥부와 놀부」이지만, 아래 규칙은 이후 추가되는 모든 전래동화 에피소드에 동일하게 적용한다.

### 핵심 목표

- 유아와 초등 저학년이 부모와 함께 별도 설명 없이 조작할 수 있다.
- 영상처럼 자연스럽게 장면이 이어지되, 아이가 중요한 순간에 능동적으로 선택한다.
- 덜 바람직한 선택도 벌주거나 낙인찍지 않고 결과를 살펴보고 다시 생각할 기회를 준다.
- 자막 또는 소리 중 하나만 사용해도 이야기와 선택을 온전히 이해할 수 있다.
- 짧은 이동 시간이나 가족의 자투리 시간 안에 한 에피소드를 마칠 수 있다.
- 새 에피소드가 추가되어도 플레이어의 상호작용 방식과 품질 기준은 일관되어야 한다.

### 기본 사용 맥락

- 권장 연령: 유아 및 초등학교 저학년, 보호자 공동 사용 권장
- 권장 회차 길이: 6~8분
- 장면 수: 8~12개
- 선택 횟수: 3회 안팎
- 장면 길이: 20~40초
- 선택 간격: 45~90초
- 우선 기기: 휴대전화 세로 화면, 터치 입력

## 2. UX 원칙

### 아이를 재촉하지 않는다

- 선택에는 제한 시간을 두지 않는다.
- 선택 화면, 피드백 화면, 엔딩에서는 자동으로 다음 장면으로 넘어가지 않는다.
- 이야기 장면만 내레이션 종료 후 자동 진행할 수 있으며, 언제든 일시정지할 수 있어야 한다.

### 행동을 돌아보되 아이를 평가하지 않는다

- `정답`, `오답`, `실패`, `벌`, 점수 감점 같은 표현을 사용하지 않는다.
- 붉은 X, 큰 경고음, 위협적인 흔들림 효과를 사용하지 않는다.
- 결과 문구는 인물의 행동과 주변에 미친 영향을 설명하고, 아이의 성격을 평가하지 않는다.
- 덜 바람직한 선택에도 `다시 생각해 보기`와 `이대로 이야기 계속하기`를 함께 제공한다.
- 모든 선택은 다음 이야기로 이어져야 하며 막다른 화면을 만들지 않는다.

### 부모와 아이가 함께 이야기하게 한다

- 선택 이유를 말할 수 있는 짧은 질문을 제공한다.
- 선택 직후 설명은 한 번에 한 가지 교훈만 전달한다.
- 엔딩에서는 선택을 맞고 틀린 것으로 나열하지 않고 `우리가 고른 길`로 보여준다.
- 부모에게는 평가보다 경청을 돕는 질문을 제공한다.

### 소리와 움직임에 의존하지 않는다

- 음소거 상태에서도 자막과 시각 정보만으로 완주할 수 있어야 한다.
- 그림을 보지 못해도 화면 읽기 프로그램이 핵심 행동과 표정을 이해할 수 있어야 한다.
- 애니메이션을 줄여도 이야기 순서나 선택 결과가 달라지지 않아야 한다.

## 3. 모바일 우선 화면 흐름

### 3.1 홈·에피소드 책장

필수 요소:

- 서비스 제목과 한 문장 소개
- 에피소드 표지 카드
- 에피소드별 예상 시간과 완료 상태
- 저장된 진행이 있으면 `이어보기` 버튼
- 저장된 진행이 없으면 `이야기 보기` 버튼
- 자막·소리 등 공통 설정으로 들어가는 버튼

상호작용 규칙:

- 홈에서 플레이어 시작까지 주요 탭은 최대 2회로 한다.
- 에피소드 카드 전체를 누를 수 있게 하되, 카드 내부 버튼의 이름도 명확히 제공한다.
- 아직 공개되지 않은 에피소드는 누를 수 없는 흐린 카드보다 `준비 중` 상태를 텍스트로 표시한다.

### 3.2 에피소드 소개

필수 요소:

- 제목, 표지, 짧은 줄거리
- 권장 연령과 예상 시간
- 오늘 함께 생각할 질문 1개
- `이야기 시작` 버튼
- 저장된 진행이 있으면 `이어보기`와 `처음부터` 버튼

`이야기 시작`은 브라우저의 오디오 재생 권한을 얻는 명시적 사용자 동작으로 사용한다. 페이지 진입만으로 소리를 재생하지 않는다.

### 3.3 이야기 플레이어

세로 화면의 권장 배치는 다음과 같다.

1. 상단: 나가기, 장면 진행 표시, 자막·음소거 빠른 설정
2. 중앙: 배경과 인물로 구성된 장면
3. 하단: 자막, 재생·일시정지, 다음 진행 동작

규칙:

- 장면 그림은 중요한 인물과 표정이 자막이나 선택 패널 뒤에 가려지지 않는 안전 영역을 가진다.
- 진행 표시는 `3 / 10`처럼 경쟁적인 점수로 보이지 않게 작은 책장 또는 점 형태로 나타낸다.
- 내레이션 도중 페이지가 백그라운드로 이동하거나 탭이 가려지면 자동 일시정지한다.
- 네트워크나 오디오 오류가 발생해도 자막은 즉시 보이고 다음 진행은 막히지 않는다.

### 3.4 선택 화면

- 이야기 재생을 멈추고 질문과 2개의 선택지를 표시한다. 특별한 경우에만 3개까지 허용한다.
- 선택지는 짧은 제목과 한 줄 설명을 사용한다.
- 색만으로 좋은 선택과 덜 좋은 선택을 구분하지 않는다.
- 질문과 선택지는 화면 읽기 프로그램에서 자연스러운 순서로 읽혀야 한다.
- 선택지가 나타나면 키보드 포커스를 질문 제목으로 이동한다.
- 빠른 연속 탭으로 선택이 두 번 처리되지 않도록 첫 입력 후 약 400ms 동안 중복 입력을 막는다.

### 3.5 결과·다시 생각하기

결과 화면은 다음 순서로 구성한다.

1. 무슨 일이 생겼는지 한두 문장으로 설명
2. 등장인물이 어떤 마음일지 한 문장으로 연결
3. 아이가 생각해 볼 짧은 질문
4. 다음 행동 버튼

덜 바람직한 선택에서는 `다시 생각해 보기`를 기본 강조 버튼으로, `이대로 이야기 계속하기`를 보조 버튼으로 제공한다. 같은 선택을 반복하더라도 꾸짖는 문구를 추가하지 않는다.

### 3.6 장면 전환

- 기본 전환은 300~500ms의 페이드 또는 책장 넘김 효과를 사용한다.
- 전환 중에는 중복 입력을 받지 않는다.
- `동작 줄이기`가 활성화되면 페이드, 확대, 흔들림을 제거하고 즉시 전환한다.
- 갑작스러운 번쩍임, 빠른 화면 흔들림, 큰 음량 변화는 사용하지 않는다.

### 3.7 엔딩·부모 대화 가이드

필수 요소:

- 이야기의 핵심 교훈 1문장
- `우리가 고른 길` 형태의 선택 요약
- 부모와 아이가 나눌 열린 질문 2개
- `다시 보기`, `책장으로` 버튼

열린 질문 예시:

- “흥부가 제비를 도와줄 때 어떤 마음이었을까?”
- “우리라면 오늘 누구에게 어떤 친절을 베풀 수 있을까?”

질문은 아이가 특정 답을 말하도록 유도하지 않으며, 부모에게는 `답을 고쳐 주기보다 이유를 먼저 들어 주세요`라는 짧은 안내를 제공한다.

## 4. 화면·입력 규격

### 터치 타깃

- 일반 아이콘 버튼: 최소 48×48px
- 핵심 선택 버튼: 최소 높이 56px, 권장 높이 64px
- 버튼 사이 간격: 최소 12px
- 주요 선택과 재생 버튼은 휴대전화 하단의 엄지 도달 영역에 배치한다.
- iOS와 Android의 안전 영역을 고려해 하단 패딩에 `safe-area-inset-bottom`을 반영한다.

### 글자와 자막

- 기본 본문: 20px 이상
- 핵심 자막: 22~28px
- 줄 높이: 1.45 이상
- 자막 한 큐: 최대 2줄 권장
- 어려운 한자어, 긴 피동문, 비유적인 처벌 표현을 피한다.
- 긴 문구에서도 버튼 텍스트가 잘리거나 글자가 겹치지 않아야 한다.

### 반응형 규칙

- 최소 지원 폭은 320px이다.
- 320px부터 767px까지는 세로 단일 열을 기본으로 한다.
- 넓은 가로 화면에서는 장면과 자막·조작부를 좌우로 나눌 수 있다.
- 화면 방향이 바뀌어도 현재 장면과 선택은 유지한다.
- 200% 확대와 운영체제 큰 글꼴에서도 가로 스크롤과 핵심 콘텐츠 손실이 없어야 한다.

## 5. 자막·음소거·재생 설정

### 기본값

- 자막: 켜짐
- 소리: 브라우저 정책을 존중하며 `이야기 시작` 탭 이후 재생
- 자동 재생: 이야기 장면에서만 켜짐
- 동작 줄이기: 운영체제 설정을 기본으로 따름

### 제어 규칙

- 자막과 음소거 버튼은 플레이어에서 항상 접근 가능해야 한다.
- 음소거는 배경음, 효과음, 내레이션을 모두 끄되 재생 진행에는 영향을 주지 않는다.
- 자막을 꺼도 선택 질문과 버튼, 중요한 결과 문구는 숨기지 않는다.
- 설정 변경은 즉시 반영하고 다음 방문에도 유지한다.
- 누락되거나 재생할 수 없는 오디오가 있어도 텍스트 폴백으로 진행한다.

## 6. 접근성 요구사항

### 의미 구조와 키보드

- `header`, `main`, `nav` 등 의미 있는 랜드마크와 올바른 제목 계층을 사용한다.
- 클릭 가능한 요소는 실제 `button` 또는 `a`로 구현한다.
- Enter와 Space로 모든 버튼을 조작할 수 있어야 한다.
- Esc는 플레이어 일시정지 메뉴를 연다.
- 선택 결과를 닫은 뒤 포커스는 다음 장면을 진행하는 버튼으로 이동한다.
- 모든 포커스 가능한 요소에 명확한 포커스 표시를 제공한다.

### 화면 읽기 프로그램

- 장면 변경 안내는 짧은 `aria-live="polite"` 메시지로 제공한다.
- 자막 전체를 live 영역에 반복해서 넣어 내레이션과 중복 낭독하지 않는다.
- 이야기 이해에 필요한 장면 이미지는 행동과 표정을 간결하게 설명한다.
- 장식용 이미지와 배경 레이어는 보조 기술에서 숨긴다.
- 버튼의 접근 가능한 이름만으로 동작을 이해할 수 있어야 한다.

### 시각·청각·움직임

- 일반 텍스트 명암비는 최소 4.5:1, 큰 글자와 핵심 UI 경계는 최소 3:1을 충족한다.
- 상태와 의미를 색만으로 전달하지 않는다.
- 음소거 상태에서도 이야기, 질문, 결과 정보가 모두 제공된다.
- 내레이션과 자막의 의미가 일치해야 한다.
- `prefers-reduced-motion`을 지원한다.
- 번쩍임, 급격한 확대, 반복 흔들림을 사용하지 않는다.

## 7. 이어보기와 설정 저장

### 저장 키

- 공통 설정: `storybook:settings:v1`
- 에피소드 진행: `storybook:progress:<episodeId>`

공통 설정에 저장할 항목:

- `captionsEnabled`
- `muted`
- `reducedMotionOverride`
- `updatedAt`

에피소드 진행에 저장할 항목:

- `episodeId`
- `contentVersion`
- `sceneId`
- `phase`
- `selectedChoices`
- `visitedSceneIds`
- `completed`
- `updatedAt`

### 저장 시점

- 새 장면에 진입할 때
- 선택을 확정할 때
- 피드백에서 다음 진행을 선택할 때
- 에피소드를 완료할 때
- 페이지가 백그라운드로 이동할 때

### 복구 규칙

- 이야기 장면 도중 종료한 경우 해당 장면의 처음부터 다시 시작한다.
- 선택을 기다리던 중 종료한 경우 같은 선택 화면으로 돌아온다.
- 피드백 중 종료한 경우 선택 결과를 다시 보여준다.
- 완료한 에피소드는 홈에서 완료 상태로 표시하며 `다시 보기`를 제공한다.
- 저장값은 사용하기 전에 데이터 스키마로 검증한다.
- 손상된 저장값은 안전하게 초기화하고 `저장된 이야기를 불러오지 못해 처음부터 시작할게요`라고 안내한다.
- localStorage를 사용할 수 없으면 현재 탭의 메모리 상태로 계속 진행하며 저장 실패가 이야기를 막지 않아야 한다.
- 개인 이름, 나이, 음성, 계정 등 개인 정보는 저장하지 않는다.

### 콘텐츠 버전 변경

- 저장된 `contentVersion`과 현재 에피소드 버전이 같고 `sceneId`가 존재하면 정상 복구한다.
- 버전이 다르지만 장면 ID가 여전히 유효하면 현재 장면 시작점으로 복구할 수 있다.
- 장면 ID가 사라졌다면 에피소드를 처음부터 시작하고 짧게 안내한다.
- 콘텐츠별 마이그레이션이 필요하면 데이터에 명시된 대체 장면 ID를 사용한다.

## 8. 플레이어 상태 모델

### 주요 상태

| 상태 | 의미 | 허용되는 주요 동작 |
| --- | --- | --- |
| `loading` | 에피소드 데이터와 첫 장면을 준비 중 | 오류 표시, 다시 시도 |
| `ready` | 시작 전 대기 | 시작, 나가기 |
| `playing` | 장면 내레이션과 연출 재생 중 | 일시정지, 음소거, 자막 변경 |
| `awaitingChoice` | 아이의 선택을 기다리는 중 | 선택, 일시정지, 나가기 |
| `showingFeedback` | 선택 결과와 생각 질문 표시 | 다시 생각하기, 계속하기 |
| `transitioning` | 다음 장면으로 전환 중 | 설정 변경 외 입력 잠금 |
| `completed` | 에피소드 완료 | 다시 보기, 책장으로, 부모 가이드 |
| `error` | 데이터 또는 필수 자산 오류 | 다시 시도, 책장으로 |

`paused`는 위 상태를 대체하기보다 현재 상태 위에 열리는 오버레이 상태로 관리한다. 일시정지를 닫으면 이전 상태로 돌아간다.

### 상태에 보관할 값

- 에피소드 ID와 콘텐츠 버전
- 현재 장면 ID
- 현재 단계
- 확정한 선택 목록
- 방문한 장면 목록
- 자막·음소거 설정
- 마지막 갱신 시각

DOM 요소, 오디오 객체, 애니메이션 인스턴스는 직렬화하거나 저장하지 않는다.

### 상태 전환 이벤트

- `START`
- `SCENE_ENDED`
- `SELECT_CHOICE`
- `RETRY_CHOICE`
- `CONTINUE`
- `PAUSE`
- `RESUME`
- `COMPLETE`
- `LOAD_FAILED`
- `RESET_PROGRESS`

모든 분기와 전환은 단일 상태 리듀서에서 처리한다. 같은 이벤트가 빠르게 반복되어도 다음 장면 진입과 저장은 한 번만 발생해야 한다.

## 9. 오류와 성능 폴백

- 현재 장면의 텍스트를 우선 로드하고 시각·음향 자산은 점진적으로 표시한다.
- 현재 장면 자산과 다음 장면 자산까지만 우선 선로딩한다.
- 이미지 누락 시 대체 텍스트와 단색 배경으로 계속 진행한다.
- 내레이션·BGM·효과음 누락 시 자막과 시각 피드백으로 계속 진행한다.
- 에피소드 JSON 자체가 유효하지 않으면 플레이어 대신 이해하기 쉬운 오류 화면과 `책장으로`를 제공한다.
- 연결이 느릴 때는 무한 스피너 대신 `이야기를 준비하고 있어요` 상태와 다시 시도 동작을 제공한다.

### 10.4 콘텐츠 안전

- 신체 폭력, 상처, 위협을 직접 묘사하거나 시각화하지 않는다.
- 놀부의 박 장면은 공포나 파괴보다 집안일, 정리 소동, 예상 밖의 불편처럼 회복 가능한 결과로 표현한다.
- `나쁜 아이`, `욕심쟁이라 벌받았다`처럼 인격을 낙인찍지 않는다.
- 가난, 실수, 가족 갈등을 조롱하거나 아이의 책임으로 돌리지 않는다.
- 덜 바람직한 선택에도 감정을 알아차리고 행동을 바꿀 경로가 있다.
- 무서운 효과음, 갑작스러운 비명, 위협적인 화면 흔들림을 사용하지 않는다.
- 저학년이 이해할 수 있는 낱말과 짧은 문장을 사용한다.
- 부모 질문은 하나의 답을 강요하지 않는 열린 질문이다.
- 자막, 내레이션, 화면 문구의 의미가 서로 모순되지 않는다.

### 10.5 에피소드 데이터 검증

- 에피소드, 장면, 선택 ID가 각각 유일하다.
- 필수 메타데이터, 교훈, 부모 대화 질문이 존재한다.
- 모든 다음 장면 참조가 실제 장면 ID를 가리킨다.
- 시작 장면에서 최소 하나의 엔딩에 도달할 수 있다.
- 어디에서도 도달할 수 없는 고아 장면이 없다.
- 의도하지 않은 무한 순환이 없다.
- 선택 장면에는 2~3개의 선택지가 있다.
- 모든 선택에는 피드백과 다음 경로가 있다.
- 내레이션이 있으면 대응하는 자막이 있다.
- 서사에 필요한 시각 장면에는 대체 텍스트가 있다.
- 참조하는 이미지·오디오 파일이 존재하고 파일명 대소문자가 일치한다.
- 모든 가능한 분기 경로를 자동 그래프 순회로 완주할 수 있다.

## 11. 권장 자동화 범위

- 상태 리듀서와 저장 복구: 단위 테스트
- 에피소드 스키마와 분기 그래프: 데이터 검증 테스트
- 선택·피드백·포커스 이동: 컴포넌트 테스트
- 신규 시작부터 엔딩까지 주요 분기: 브라우저 자동화 테스트
- 휴대전화 뷰포트와 이어보기: 브라우저 자동화 테스트
- 접근성 정적 위반: axe 자동 검사
- 문구의 연령 적합성과 콘텐츠 안전: 자동 검사 결과에 의존하지 않고 사람이 최종 검수

## 12. 출시 수용 기준

다음 조건을 모두 만족해야 출시 가능 상태로 본다.

1. 320px 화면과 200% 확대에서 가로 스크롤, 핵심 콘텐츠 손실, 버튼 겹침이 없다.
2. 일반 조작은 최소 48×48px, 선택 버튼은 최소 56px 높이를 충족한다.
3. 선택에는 시간 제한이 없고 빠른 연속 탭에도 한 번만 처리된다.
4. 자막은 기본으로 켜지며 음소거 상태로 전체 에피소드를 완주할 수 있다.
5. 자막, 내레이션, 선택 결과가 같은 의미를 전달한다.
6. 새로고침 또는 재방문 시 마지막 장면, 대기 중인 선택, 선택 결과 중 적절한 위치로 복귀한다.
7. 손상된 저장값, 오디오 오류, 이미지 오류가 있어도 안전하게 복구하거나 텍스트로 진행한다.
8. 모든 선택에 부드러운 피드백과 다음 경로가 있고 막다른 화면이 없다.
9. 덜 바람직한 선택을 한 아이를 꾸짖거나 낙인찍거나 겁주는 문구·연출이 없다.
10. 키보드와 대표 화면 읽기 프로그램으로 홈부터 엔딩까지 완주할 수 있다.
11. 자동 접근성 검사에서 심각 또는 중대한 위반이 없다.
12. 모든 에피소드 데이터 검증과 모든 분기 완주 테스트를 통과한다.
13. 지원 대상 모바일·태블릿·데스크톱 환경에서 프로덕션 빌드가 정상 동작한다.
14. 새 에피소드는 플레이어 코드를 수정하지 않고 에피소드 데이터와 자산 등록만으로 추가할 수 있다.
