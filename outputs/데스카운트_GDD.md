# 데스 카운트 — 상세 시스템 기획서

버전 1.0 · 2026-09-07 · 개발팀 논의용

## 1. 목적과 범위

15인이 룸 코드로 접속해 공통 카운트를 올리고 비밀 함정 숫자를 피하는 모바일 실시간 심리·눈치 게임이다. 모바일 웹/앱을 대상으로 하며, 목표 세션 길이는 5~10분, 세션 형식은 3판 2선승제다. 본 문서는 원안의 규칙을 유지하며 입력 판정, 쿨타임, 실시간 동기화, 개인 힌트, 아트·사운드 피드백과 QA 기준을 구체화한다. 게임 실행 코드나 완성된 아트·음원은 이 산출물의 범위에 포함하지 않는다.

**명세의 구분:** 원안의 게임 규칙은 고정한다. 원안에 없는 시간 경계·패킷 필드·처리 순서는 구현 기준안으로 명시한다. 승리 귀속 등 게임 결과를 바꾸는 미정 사항은 11절에 남기며 임의의 대체 규칙을 추가하지 않는다.

## 2. 게임 규칙

| 항목 | 규칙 |
|---|---|
| 참가 | 룸 코드 기반 15인 동시 접속 |
| 카운트 | 초기 확정값 0, 유효 입력 판정마다 다음 숫자 1개를 처리 |
| 비밀 함정 | 서버가 1~15 중 하나를 추첨하고 비공개 유지. 본 문서의 초기화 기준안은 매 라운드 추첨 |
| 단독 입력 | 200ms 동안 서로 다른 유효 입력자가 1명일 때 단독 입력으로 확정 |
| 단독 안전 입력 | 해당 숫자가 함정이 아니면 카운트를 확정하고 전원 쿨타임 적용 |
| 단독 함정 입력 | 해당 숫자를 누른 플레이어 즉시 탈락. 판정 후 추가 카운트 진행 없음 |
| 크래시 | 동일 판정 창에 서로 다른 플레이어 2명 이상이 입력하면 그 숫자가 새로운 마지막 숫자가 됨 |
| 크래시 결과 | 원래 함정 숫자와 무관하게 라운드 종료. 창 안의 입력자는 전원 탈락, 나머지는 전원 생존 |
| 개인 힌트 | 라운드마다 중복 없이 무작위 3명에게만 실제 함정에 관한 참인 단편 텍스트 제공 |
| 쿨타임 | 단독 안전 숫자 확정마다 서버가 500~1500ms를 새로 추첨. 모든 플레이어에게 동일 적용 |

원안의 ‘마지막 함정 숫자’ 취지에 따라 단독 함정도 라운드 종료로 해석한다. 3판 2선승과 연결되는 승수·다음 라운드 참가 규칙은 별도 확정이 필요하다. 이전 라운드 탈락자를 다음 라운드에서 자동 복귀시키거나 영구 제외하는 규칙은 여기서 추가하지 않는다.

## 3. 서버 권위와 시간 기준

서버가 카운트, 함정, 입력자 집합, 탈락, 쿨타임, 라운드 종료를 유일하게 확정한다. 클라이언트가 보내는 숫자·시각·생존 여부는 판정 근거로 신뢰하지 않는다.

한 룸의 이벤트는 단일 순서로 처리한다. 룸을 담당하는 권위 처리 지점에 입력이 들어온 시각을 `receivedAt`으로 기록하며, 이 지점의 단조 증가 시계를 판정에 사용한다. 여러 연결에서 들어온 입력도 동일한 큐에서 순서화한다. 타이머 콜백 실행이 늦더라도 마감 시각 이하로 수신 기록된 이벤트를 먼저 처리한 뒤 창을 확정한다. 분산된 서버들의 서로 다른 시계를 섞어 비교하지 않는다.

서버 도착 시각 기준이므로, 두 사용자가 실제로 동시에 눌러도 네트워크 지연 차이로 같은 창에 들어오지 않을 수 있다. 이는 본 규칙의 판정 기준이며 클라이언트 시각으로 소급 판정하지 않는다. 화면의 시간 표시는 서버 시각과의 오프셋을 추정해 보정하되, 표시 오차가 실제 판정을 변경하지 않는다.

## 4. 상태 기계

| 상태 | 서버 처리 | 공통 버튼 |
|---|---|---|
| `LOBBY` | 접속 및 참가 상태 관리 | 입력 불가 |
| `ROUND_READY` | 참가 집합 고정, 카운트 0, 함정·힌트 생성 | 입력 불가 |
| `OPEN` | 첫 유효 입력을 기다림 | 참가자 입력 가능 |
| `COLLECTING` | 첫 입력부터 고정 200ms 동안 같은 숫자의 입력자 수집 | 누른 본인만 중복 입력 차단, 나머지는 입력 가능 |
| `COOLDOWN` | 확정된 안전 숫자 유지, `unlockAt` 이전 입력 거절 | 전원 비활성 |
| `ROUND_ENDED` | 종료 사유·탈락자·생존자 결과 고정 | 입력 불가 |

전이: `ROUND_READY → OPEN → COLLECTING → COOLDOWN → OPEN`을 반복한다. `COLLECTING`에서 크래시 또는 단독 함정이 확정되면 `ROUND_ENDED`로 전이한다. 종료된 라운드의 늦은 입력은 다음 라운드로 넘기지 않는다.

## 5. 동시 입력 처리 — 핵심 명세

### 5.1 고정 판정 창

현재 확정 카운트를 `c`, 다음 판정 숫자를 `n=c+1`이라 한다. `OPEN`에서 첫 유효 입력이 수신된 시각 `t0`에 `n`의 판정 창을 연다.

- 창은 **`[t0, t0+200ms]`**로 고정한다. 정확히 마감 시각에 도착한 입력도 포함한다. 원안의 ‘0.2초 이내’를 양끝 포함으로 해석한다. 종료 처리는 서버 시각이 마감을 지난 뒤 수행한다.
- 두 번째 이후 입력으로 창을 연장하지 않는다. 예를 들어 0ms·190ms·380ms 도착 시 앞의 두 명만 포함한다.
- 같은 플레이어의 재전송·연타·복수 연결 입력은 한 명으로 계산한다.
- 참가 자격을 검증한 서로 다른 플레이어만 입력자 집합 `S`에 추가한다.
- 첫 입력 직후에는 확정 카운트를 올리거나 전역 쿨타임을 시작하지 않는다. 다른 플레이어가 남은 창에 입력할 수 있어야 한다.
- 본인의 탭 접수 표시는 제공할 수 있지만, 접수는 단독 안전 성공을 의미하지 않는다.

### 5.2 판정 우선순위

마감 시각을 지난 뒤 해당 창의 수신 이벤트를 모두 반영하고 아래 순서로 한 번만 확정한다.

1. `|S| ≥ 2`: **크래시가 최우선**이다. 숫자 `n`을 마지막 숫자로 확정하고 `S` 전원 탈락, 미입력 참가자 전원 생존, 라운드 종료. 원래 함정과 비교하지 않는다.
2. `|S| = 1`이며 `n = bomb`: 숫자 `n` 확정, 해당 입력자 탈락, 단독 함정으로 라운드 종료.
3. `|S| = 1`이며 `n ≠ bomb`: 안전 숫자 `n` 확정, 랜덤 쿨타임 시작.

두 번째 입력 수신 시 크래시 발생은 논리적으로 확실해지지만, **탈락자 집합은 200ms 창 전체를 수집한 후 확정**한다. 두 번째 입력에서 창을 닫으면 이후 창 안에 들어온 세 번째 입력자를 잘못 생존시키므로 금지한다. 크래시 연출은 이 최종 결과 수신 즉시 시작한다. 여기서 ‘즉시’는 별도의 게임 연출 대기 없이 서버 판정 후 시작한다는 의미다.

단독 함정 역시 첫 입력 순간에 종료하지 않는다. 창 안에서 추가 입력이 들어오면 크래시가 우선되어야 하므로 200ms 창과 서버 처리 시간만큼의 판정 대기가 필요하다.

### 5.3 입력 유효성

서버는 인증된 연결에서 플레이어를 식별하고 `roundId`, `gateId`, `requestId`를 검증한다. 다른 라운드, 이전 입력 기회, 비참가자, 종료 후 입력, 쿨타임 입력은 거절한다. 클라이언트가 지정한 다른 플레이어 ID로 참가자를 바꿀 수 없다.

`gateId`는 한 번의 입력 가능 구간과 그 뒤 수집 창을 식별한다. 다음 `OPEN`에서 새 값으로 바꾸므로, 이전 창에 보낸 패킷이 지연되어 다음 숫자를 우발적으로 누르는 것을 막는다. `requestId`는 한 번의 탭을 식별한다. 같은 ID 재전송에는 기존 처리 결과를 반환하고 상태를 다시 변경하지 않는다. 다른 ID를 보낸 같은 사용자도 한 창에서 한 번만 집계한다.

### 5.4 시간 예시

| 상대 시각 | 이벤트 | 처리 |
|---|---|---|
| 0ms | A가 숫자 4의 첫 입력 | 창 `[0,200]` 시작 |
| 120ms | B 입력 | 동일 숫자 4의 집합에 추가 |
| 199ms | C 입력 | 동일 집합에 추가 |
| 200ms | D 입력 | 창의 마지막 경계에 포함 |
| 201ms | E 입력 | 창 밖. 종료 확정 후 거절 |
| 200ms 초과 시점 | 결과 확정·전달 | A·B·C·D 탈락, E와 나머지 참가자 생존 |

함정이 4여도 위 결과는 `CRASH`다. 함정이 12여도 동일하며 12까지 진행하지 않는다.

## 6. 랜덤 쿨타임

안전 숫자 확정 시에만 서버가 정수 밀리초 `D ∈ [500,1500]`를 균등 추첨한다. 시작 시각 `committedAt`은 실제 상태 확정 시각이고, `unlockAt=committedAt+D`다. 타이머 지연 때문에 쿨타임이 짧아지지 않도록 입력 창의 명목 마감이 아닌 실제 확정 시각을 사용한다.

- 유효성 구간: `receivedAt < unlockAt`이면 거절, `receivedAt ≥ unlockAt`이면 현재 입력 기회의 참가 자격을 검증한 후 접수한다.
- 쿨타임 입력을 예약하거나 저장해 해제 직후 자동 적용하지 않는다.
- 모든 플레이어는 동일한 `unlockAt`을 사용한다. 각 기기가 서로 다른 쿨타임을 추첨하지 않는다.
- 클라이언트는 결과 패킷의 해제 시각을 기준으로 잔여 시간을 표시하고, 서버는 매 프레임 잔여 시간을 전송하지 않는다.
- 해제 알림 전달이 늦더라도 서버는 수신 시각으로 해제 여부를 판단한다. 다음 `gateId`는 쿨타임 결과에서 미리 전달하여 해제 후 입력이 가능하게 한다.
- 크래시·단독 함정으로 끝났다면 쿨타임을 새로 생성하지 않는다.

예: 첫 입력 0ms, 단독 안전 확정 201ms, 추첨값 900ms이면 해제는 1101ms다. 앞부분은 200ms 동시 입력 창과 확정 처리 시간이고 뒤 900ms만 쿨타임이다.

## 7. 동기화와 패킷 기준

가벼운 양방향 연결을 사용하고, 서버 이벤트에 `roundId`와 단조 증가 `seq`를 넣는다. 전송 구현은 WebSocket을 기준안으로 한다. 필드 이름은 가독성을 위한 논리 이름이며, 바이너리 압축 등 별도 최적화를 필수로 추가하지 않는다.

| 방향·이벤트 | 주요 필드 | 의미 |
|---|---|---|
| C→S `PRESS` | `roundId, gateId, requestId` | 숫자·기기 시각 없이 현재 입력 기회에 탭 요청 |
| S→C `PRESS_ACK` | `roundId, requestId, status` | 본인에게만 접수·중복·거절 반환. 게임 결과 확정과 구분 |
| S→전체 `ROUND_START` | `roundId, seq, count:0, phase, gateId, serverNow` | 공개 라운드 초기 상태 |
| S→개인 `HINT` | `roundId, text` | 선택된 당사자에게만 개인 힌트 |
| S→전체 `COUNT_RESOLVED` | `roundId, seq, count, phase, unlockAt, nextGateId, serverNow` | 단독 안전 카운트·공통 해제 시각 |
| S→전체 `ROUND_RESULT` | `roundId, seq, count, reason, eliminatedIds, survivorIds` | `CRASH` 또는 `BOMB`와 참가자 결과 |
| S→개인 `SNAPSHOT` | `roundId, seq, count, phase, gateId, nextGateId?, unlockAt?, result?, ownHint?, ownSubmission, serverNow` | 재접속·누락 복구용 권위 상태. 쿨타임이면 nextGateId도 포함 |

패킷 예:

```json
{"type":"PRESS","roundId":"r1","gateId":4,"requestId":"p7-19"}
{"type":"COUNT_RESOLVED","roundId":"r1","seq":8,"count":4,"phase":"COOLDOWN","unlockAt":11000,"nextGateId":5,"serverNow":10100}
```

전송 시각은 룸 내 단조 증가 경과 밀리초로 표현한다. 클라이언트는 왕복 측정으로 같은 시간 축에 맞춘다. `seq`가 지난 공개 상태 이벤트는 무시하고, 누락이 감지되면 스냅샷으로 복구한다. 개인 ACK·힌트는 공개 상태 `seq` 누락 판단과 분리한다. 스냅샷 적용 후 그 버전 이하의 상태 이벤트가 뒤늦게 와도 되돌리지 않는다.

재접속은 동일한 인증 참가자 ID에 연결한다. 접속이 끊겨도 이미 접수한 입력은 취소하지 않는다. 단절 중에도 서버 창과 쿨타임은 계속 진행한다. 복구 전에는 버튼을 비활성화하고 현재 스냅샷으로 돌아온다. 접속이 끊겼다는 이유만으로 별도 탈락을 부과하지 않는다. 실제 장기 이탈·룸 종료 정책은 미정이다.

## 8. 비대칭 힌트

라운드 초기화에서 참가자 중 서로 다른 3명을 서버가 추첨한다. 이 세 명에게만 함정 숫자에 대해 참인 단편 텍스트를 보낸다. 나머지는 ‘개인 힌트 없음’을 표시하며 다른 사람의 힌트를 받지 않는다.

문구 예: ‘함정 숫자는 홀수다’, ‘함정 숫자는 짝수다’, ‘함정 숫자는 10 이상이다’, ‘함정 숫자는 10 미만이다’. 서버는 실제 함정에 부합하는 후보만 사용한다. 예를 들어 함정 12라면 ‘짝수다’와 ‘10 이상이다’는 가능하고 ‘홀수다’는 금지한다. 후보 구성과 문구별 추첨 가중치는 콘텐츠 확정 대상이다. 세 사람에게 서로 다른 힌트를 반드시 제공한다는 조건은 원안에 없다.

함정 원본 값, 타인의 힌트, 힌트 배정자 목록을 공개 패킷이나 전체 클라이언트 상태에 넣지 않는다. 개인 힌트 재전송·재접속 복구도 인증된 당사자에게만 수행한다. 힌트는 텍스트로만 개인 화면에 제공하여 오프라인 심리전의 정보 비대칭을 유지한다.

## 9. 화면 및 아트 명세

모바일 세로 화면의 정보 우선순위는 중앙 공통 숫자, 하단의 큰 단일 입력 버튼, 개인 힌트, 라운드 상태 순이다. 룸 진입 화면에는 룸 코드와 참가 인원을 표시한다. 별도 재화·아이템·스킬 UI는 추가하지 않는다.

| 화면 상태 | 숫자·버튼 표현 | 피드백 |
|---|---|---|
| 입력 가능 | 마지막 확정 숫자, 활성 ‘카운트’ 버튼 | 입력 가능한 명확한 대비 |
| 본인 입력 접수 | 확정 숫자 유지, 본인 버튼 잠금 | 짧은 눌림 반응 및 ‘판정 중’ |
| 타인 입력 수집 중 | 다른 참가자에게는 기존 활성 상태 유지 | 전역 비활성화나 확정 성공 연출 금지 |
| 안전 확정·쿨타임 | 새 숫자, 비활성 버튼 | 잔여 시간 진행 표시 |
| 크래시 | 새 마지막 숫자 강조, 버튼 잠금 | 화면 전체 셰이크·붉은 점멸·‘크래시’ 텍스트, 본인 생존/탈락 |
| 단독 함정 | 마지막 숫자, 버튼 잠금 | ‘함정’ 텍스트, 본인 생존/탈락 |

크래시 연출은 권위 결과 수신 프레임에서 시작하며 약 300ms의 짧은 감쇠 셰이크와 한 차례 붉은 오버레이 펄스를 기준으로 한다. 색상만으로 결과를 전달하지 않고 텍스트를 함께 사용한다. 반복 섬광으로 시간을 늘리지 않으며 결과 텍스트는 연출 뒤 안정적으로 유지한다. 이 수치는 아트 제작 기준안이다.

제작 대상: 버튼 활성·접수·쿨타임·종료 상태, 숫자 타이포그래피, 힌트 텍스트 영역, 크래시 오버레이와 셰이크, 개인 결과 표시. 기기별 화면 크기·안전 영역에서 버튼과 힌트가 겹치지 않아야 한다.

## 10. 사운드 명세

서버 판정을 청각적으로 구분하고, 대면 대화를 가리지 않는 짧은 효과음을 사용한다. 아래 길이는 사운드 제작 기준안이다.

| 큐 | 트리거 | 제작·재생 기준 |
|---|---|---|
| 탭 | 로컬 버튼의 유효한 눌림 | 20~50ms 중립 클릭. 안전 성공을 암시하지 않음 |
| 안전 카운트 | `COUNT_RESOLVED` 최초 적용 | 80~150ms 확정음 1회. 숫자에 따른 비밀 단서를 추가하지 않음 |
| 쿨타임 해제 | 해당 입력 기회가 사용 가능해짐 | 50~100ms 준비음. 시각 표시와 함께 사용 |
| 크래시 | `ROUND_RESULT: CRASH` 최초 적용 | 400~700ms 충돌·기폭음, 셰이크 시작과 함께 재생 |
| 단독 함정 | `ROUND_RESULT: BOMB` 최초 적용 | 300~600ms 기폭음, 안전 확정음·크래시와 구별 |

`roundId + seq + 큐 종류`로 결과음 중복을 방지하며 해제음은 `roundId + gateId`로 중복을 방지한다. 재전송·스냅샷 복구로 지난 효과음을 다시 재생하지 않는다. 종료 또는 라운드 변경 시 이전 예약음을 취소하고, 기폭음은 하위 효과음보다 우선한다. 판정 결과를 사운드로 먼저 예고하지 않으며 비밀 함정이나 개인 힌트를 음성으로 읽지 않는다. 힌트 대상자만의 알림음도 재생하지 않는다.

사운드가 없어도 입력·쿨타임·결과를 모두 알 수 있어야 한다. 모바일 웹의 직접 사용자 조작에서 오디오 초기화를 시도하되 게임 진행은 재생 허용이나 로딩 성공에 의존하지 않는다. 백그라운드 복귀 시 지난 해제음을 재생하지 않는다. 같은 공간의 여러 기기는 결과 도착 지연이 달라 완벽히 같은 시각에 소리가 나오는 것을 보장하지 않는다. 제작 원본은 WAV, 배포본은 대상 환경에 맞는 경량 포맷으로 준비하고 클릭 잡음·피크 클리핑을 확인한다.

## 11. 개발 전 확정이 필요한 원안의 공백

| 항목 | 현재 명세의 한계 |
|---|---|
| 3판 2선승의 승리 귀속 | 다수 생존 상황에서 누구의 승수를 올리는지 없음. 개인·팀·공동승리 등을 임의 채택하지 않음 |
| 전원 동시 입력 | 크래시 규칙상 전원 탈락·생존자 0명까지 판정 가능. 무승부·재경기·승수 처리는 미정 |
| 다음 라운드 참가자 | 이전 탈락자의 복귀 여부 및 다음 라운드 3명 힌트 배정과의 관계 미정 |
| 라운드 시작 조건 | 15인 참가 목표는 명시됨. 정원 미달 시작, 호스트, 준비·시작 권한은 미정 |
| 대기·이탈 | 아무도 누르지 않는 경우 제한 시간과 강제 진행 규칙 없음. 따라서 5~10분은 목표이며 보장 시간이 아님 |
| 함정 추첨 주기 | 원안의 ‘게임 시작’과 라운드의 관계는 불명확. 본 문서는 매 라운드 재추첨을 초기화 기준안으로 사용하며 확인 필요 |
| 종료 후 함정 공개 | 원래 함정 공개 여부 미정. 현재 공개 패킷에는 넣지 않음 |
| 단독 함정 후 종료 | 본 문서는 ‘마지막 숫자’로 라운드 종료 해석. 원안의 명시적 크래시 종료와 함께 확인 필요 |

입력 엔진과 개별 라운드 결과는 이 문서로 논의·구현할 수 있지만, 전체 세션 승자와 다음 판 진행은 위 규칙 확정 전까지 완결된 것으로 간주하지 않는다.

## 12. QA 수용 기준

서버 단위 테스트는 가상 시계를 사용해 창·쿨타임 경계를 검증한다. 통합 테스트는 15개의 독립 참가 연결로 지연·중복·연결 복구를 검증한다. 아래는 실행 결과가 아닌 구현 후 수행할 수용 테스트다.

| ID | 조건 | 기대 결과 |
|---|---|---|
| Q01 | 첫 입력만 있고 함정 아님 | 200ms 창 종료 후 카운트 1 증가, 쿨타임 1회 생성 |
| Q02 | 첫 입력 0ms, 다른 참가자 199ms | 크래시, 두 명 탈락 |
| Q03 | 첫 입력 0ms, 다른 참가자 정확히 200ms / 201ms | 200ms는 크래시에 포함. 201ms는 창 밖으로 쿨타임 또는 종료 거절 |
| Q04 | 0·190·380ms 서로 다른 입력 | 앞 두 명만 크래시 탈락, 세 번째 거절 |
| Q05 | 세 번째 참가자 199ms 추가 | 두 번째에서 조기 확정하지 않고 세 명 전원 탈락 |
| Q06 | 같은 사용자 연타·재전송·복수 연결 | 입력자 1명, 크래시 없음, 상태 변경 중복 없음 |
| Q07 | 원래 함정 숫자에서 두 명 입력 | 단독 함정 대신 크래시, 두 명 탈락 |
| Q08 | 원래 함정보다 이른 숫자에서 크래시 | 현재 숫자가 마지막, 다음 숫자로 진행 없음 |
| Q09 | 단독 함정 | 200ms 이후 1명 탈락, 쿨타임 없음 |
| Q10 | 15명 전원 창 안에 입력 | 탈락 15명·생존 0명, 세션 승수를 임의 부여하지 않음 |
| Q11 | 쿨타임 최솟값·최댓값 강제 | 각각 500ms·1500ms 동일 적용 |
| Q12 | 해제 1ms 전·정확히 해제 시각 | 전자는 거절, 후자는 올바른 gateId이면 접수 |
| Q13 | 쿨타임 동안 연타 | 예약 입력 없이 카운트 유지 |
| Q14 | 지난 roundId·gateId 패킷 도착 | 현재 숫자에 영향을 주지 않음 |
| Q15 | 타이머 처리가 지연됨 | 마감 시각 이하 기록 입력 포함, 이후 입력 제외; 확정 후 쿨타임 길이 유지 |
| Q16 | 결과 패킷 중복·과거 seq | 상태 되돌림·중복 기폭음 없음 |
| Q17 | 본인 입력 후 연결 끊김·재접속 | 접수 입력 유지, 동일 참가자 복구, 중복 집계 없음 |
| Q18 | 15명 중 힌트 수신 대상 검사 | 중복 없는 3명, 각 문구는 함정에 대해 참 |
| Q19 | 비대상자 패킷·스냅샷 검사 | 함정·타인 힌트·대상자 목록 유출 없음 |
| Q20 | 여러 기기 지연을 다르게 설정 | 최종 숫자·결과·unlockAt 일치, 서버 도착 기준으로 판정 |
| Q21 | 본인 수집 대기와 다른 사용자 UI | 본인 중복 탭만 차단, 타 사용자 창 내 입력 가능 |
| Q22 | 크래시 결과 수신 | 셰이크·붉은 펄스·텍스트 즉시 시작, 버튼 종료 잠금 |
| Q23 | 음소거·오디오 재생 불가 | 시각 정보만으로 상태와 결과 판별 가능 |
| Q24 | 함정 1 / 15 | 1도 정상 기폭 가능. 크래시가 없으면 15에서 반드시 종료, 16 진행 없음 |
| Q25 | 쿨타임 중 재접속 | nextGateId 복구 후 해제 시 정상 입력 가능 |

성능 측정은 입력 수신→처리 지연, 창 마감→실제 확정 지연, 결과 전송→클라이언트 반영 지연, 패킷 크기를 구분해 수집한다. 의도한 200ms 판정 창을 네트워크 지연으로 오인하지 않는다. 목표 기기·네트워크와 수치 SLA는 아직 주어지지 않았으므로 실측 성능을 충족했다고 주장하지 않는다.

## 13. 구현 논의용 판정 의사 코드

```text
onPress(authenticatedPlayer, request, receivedAt):
    serialize within room authority
    advance due transitions in receive-time order
    if same request already processed: return cached response
    validate roundId, gateId, participant, current phase
    if COOLDOWN or ROUND_ENDED: reject (do not queue)
    if OPEN:
        phase = COLLECTING
        candidate = count + 1
        deadline = receivedAt + 200ms
        inputPlayers = empty set
    if receivedAt > deadline: reject stale gate
    add authenticatedPlayer to inputPlayers (unique)
    acknowledge receipt only

resolveWindow():
    require monotonicNow() > deadline
    process all recorded events received at or before deadline
    if size(inputPlayers) >= 2:
        commit count = candidate, reason = CRASH
        end round; eliminate inputPlayers; survive all other participants
    else if candidate == secretBomb:
        commit count = candidate, reason = BOMB
        end round; eliminate sole inputPlayer
    else:
        commit count = candidate
        phase = COOLDOWN
        unlockAt = monotonicNow() + randomInteger(500, 1500)
        allocate nextGateId
        broadcast count, unlockAt, nextGateId
```

`advance due transitions`는 쿨타임 해제 시각부터 입력을 허용한다. 창 마감과 같은 시각의 입력은 수집에 포함하고, 마감을 지난 뒤 마감 시각 이하 수신 기록의 배출과 종료 확정을 원자적으로 수행한다. 이중 판정이나 이전 입력의 다음 숫자로의 전용을 방지한다. 종료와 카운트 변경마다 공개 상태 버전을 증가시킨다.

## 14. 독립 에이전트 검토 반영

| 역할 | 통합 내용 |
|---|---|
| 기획 | 판정 창과 쿨타임 분리, 크래시 우선, 200ms 경계 포함, 승리 귀속·추첨 주기 미정 명시 |
| 아트 | 본인 접수와 전역 비활성 구분, 확정 숫자 유지, 개인 힌트 영역, 크래시 시각 리소스 |
| QA | 중복·지연·타이머 경계·15인 전원 탈락·힌트 유출 테스트, 재접속 nextGateId 복구 |
| 사운드 | 접수·확정 큐 분리, 기폭 우선순위, 과거 이벤트 재생 방지, 개인 힌트 알림음 금지 |

검토는 문서·설계 수준이다. 실행 가능한 게임, 실제 네트워크 측정, 기기 QA 및 아트·음원 제작은 수행하지 않았다. DB 테이블은 생성하지 않았다.
