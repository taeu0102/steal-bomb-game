## 1. 기획 의도
### 간단한 조작으로 사람 사이의 긴장감 만들기
조작은 공통 버튼 하나지만, 선택은 단순하지 않게 만드는 것이 핵심이다. 지금 누르면 점수를 얻을 수 있지만 다른 사람과 겹치거나 폭탄을 누를 수 있다. 기다리면 위험을 피하지만 다른 사람이 점수를 가져간다. 반사신경만 겨루기보다 상대의 망설임과 의도를 읽는 심리전을 목표로 했다.
### 숫자가 커질수록 커지는 유혹
공통 숫자 1은 10점, 2는 20점, 3은 30점을 지급한다. 후반 숫자는 보상이 커지므로 이미 쌓은 점수를 잃을 위험과 다시 누를 동기를 함께 만든다. 이 보상은 개인의 클릭 횟수가 아니라 **현재 공통 숫자**를 기준으로 한다.
### 비대칭 정보로 대화와 눈치싸움 유도
라운드마다 무작위 3명에게만 폭탄 관련 힌트를 제공한다. 정보를 가진 사람의 행동과 말을 다른 사람이 해석하게 만들고, 오프라인 대화에서 설득이나 의심이 생기도록 설계했다. 이는 기획 의도이며 실제 대화 행동의 변화는 별도 사용자 테스트로 확인해야 한다.
### 팀원의 참여 기회 확보
개인전과 팀전을 모두 제공한다. 팀전에서는 같은 사람이 두 숫자를 연속 성공하면 다음 입력을 잠가 한 사람의 독주를 제한한다. 다른 참가자의 단독 성공이 확정되면 다시 참여할 수 있다. 같은 팀·상대 팀 어느 쪽의 성공도 해제 조건이다.
### 접속 장벽 줄이기
GPT 로그인이나 앱 설치 없이 웹에서 닉네임과 방 코드로 참여하도록 공개했다. 사람을 모으기 전에도 게임을 이해할 수 있도록 14명의 서버 봇과 혼자 연습하는 모드를 제공한다.

## 2. 최종 적용 규칙
### 입장과 승부
- 전체 15명이 입장하면 방장이 시작한다. 혼자 연습은 사람 1명과 봇 14명으로 구성한다.
- 3라운드를 모두 진행한다. 개인전은 개인 누적 점수, 팀전은 팀원 점수 합계로 우승을 결정한다.
- 최고 점수가 같으면 공동 우승이며 전원 0점이면 무승부다.
- 새 라운드는 연속 성공 기록을 초기화하고 점수는 유지한다. 새 게임은 점수도 초기화한다.
### 클릭과 점수
- 한 사람은 여러 번 클릭할 수 있다. 개인전에는 연속 성공 제한이 없다.
- 숫자 n을 단독으로 성공하면 n×10점을 획득한다. 한 사람이 1·2·3을 성공하면 누적 60점이다.
- 첫 유효 입력부터 200ms 동안 같은 숫자에 들어온 서로 다른 참가자의 입력을 수집한다.
- 2명 이상이면 충돌로 라운드를 종료한다. 해당 입력은 보상 0점이며 충돌자들은 벌칙을 받는다.
- 충돌만 한 사람은 이전 누적 점수를 유지한다. 폭탄 담당자는 이전 라운드를 포함한 누적 점수가 0점이 된다.
### 폭탄과 라운드 종료
- 일반 라운드에는 서버가 1~15 중 폭탄 숫자 하나를 비밀리에 설정한다.
- **폭탄 숫자에 도달하면 200ms 판정 창이 끝나는 즉시 라운드를 종료한다.** 단독 폭탄은 숫자 공개와 누적 0점 처리를 바로 표시하며 이후 입력을 거절한다.
- 폭탄 숫자에서 여러 명이 충돌하면 충돌자 모두 폭탄 초기화 대상이다. 이 경우 기존 충돌 연출과 1.8초 뒤 폭탄 공개를 유지한다.
- 폭탄에 도달하기 전에 충돌했다면 추가 폭탄 벌칙은 없다.
- 매 라운드 독립적으로 **20% 확률로 폭탄이 없다.** 발생률 20%는 개발 시 설정한 기본값이며 사용자 테스트로 검증된 균형 수치는 아니다.
- 폭탄 없는 라운드에서는 무작위 3명에게만 “이번 라운드에는 폭탄이 없다.” 힌트를 준다. 나머지 참가자에게는 종료 공개 전까지 알리지 않는다.
- 폭탄이 없어도 충돌하면 종료·벌칙이 발생한다. 충돌 없이 15까지 가면 모두 점수를 유지하며 종료한다.
### 팀 구성과 연속 제한
- 2팀 또는 3팀을 선택한다. 참가자는 대기실에서 자기 팀을 선택하고 방장은 전체 참가자의 팀과 팀 수를 조정할 수 있다.
- 9:6, 7:5:3처럼 인원을 자유롭게 구성한다. 전체 15명과 각 팀 최소 1명만 요구한다.
- 게임 시작 후에는 팀을 바꿀 수 없다.
- A가 1·2를 연속 성공하면 A는 30점이고 버튼이 잠긴다. B가 3을 단독 성공하면 잠금이 풀린다. 쿨타임 뒤 A가 4에 성공하면 A의 누적 점수는 70점이다.
- 다른 사람이 입력을 보냈다는 사실만으로 잠금을 풀지 않는다. 서버의 단독 성공 확정이 필요하다.

## 3. 규칙을 보완한 과정
1. **초기 기획:** 15인 실시간 눈치 게임, 비밀 폭탄, 200ms 동시 입력 충돌, 무작위 쿨타임과 3명 힌트를 중심으로 시작했다. 최초 승부 방식은 생존 기반 3판 2선승제였다.
2. **실제 플레이 구현 요청:** 문서에 그치지 않고 룸 코드로 접속하는 게임, 긴장감을 유지하는 화면과 사운드를 구현했다.
3. **충돌 후 폭탄 공개 실험:** 충돌 시 종료하고, 원래 폭탄 숫자를 나중에 공개해 담당자를 추가 벌칙자로 지정하는 방식으로 변경했다. 이 중간 버전에서는 단독 폭탄을 눌러도 계속 진행했다.
4. **포인트제 전환:** 한 사람 한 번 클릭이라는 초기 설명을 보완해 여러 번 클릭할 수 있도록 확정했다. 숫자에 따라 10점씩 커지는 보상과 폭탄 누적 0점 규칙을 적용하고, 생존 승수 대신 3라운드 점수제로 변경했다.
5. **개인전·팀전 추가:** 팀원의 참여 기회를 만들기 위해 팀전 3연속 성공 제한을 도입했다.
6. **자유 팀 편성:** 초기 3팀×5명 자동 구성에서 2팀·3팀 선택 및 자유로운 팀원 배치로 확장했다.
7. **메인 문구 변경:** “같이 누르면, 같이 끝난다”를 “공존할것인가, 혼자만 남을것인가”로 변경해 공존과 개인의 이익 사이의 선택을 드러냈다.
8. **폭탄 즉시 종료로 정정:** 사용자의 최종 의도에 맞춰 폭탄 도달 즉시 라운드를 끝내도록 수정했다. 앞서 기술한 ‘단독 폭탄 이후 계속 진행’은 개발 이력이며 현재 규칙이 아니다.
9. **폭탄 없는 예외 라운드 추가:** 폭탄 존재 자체의 불확실성을 추가했다. 폭탄이 없어도 충돌 위험은 남고, 끝까지 진행되면 점수를 보존할 수 있다.
10. **공개 및 결과물 등록:** GPT 로그인 없는 공개 접속을 확인하고 AI 결과물 페이지에 게임 소개 카드와 직접 플레이 링크를 추가했다.

## 4. 개발 작업 방식
### 역할을 나눈 에이전트 협업
- 기획: 입력 판정, 종료 조건, 힌트와 쿨타임 등 규칙을 구체화하고 변경 요청을 반영했다.
- 아트: 어두운 배경, 위험을 나타내는 오렌지·레드, 큰 카운트와 버튼, 모바일 여백과 충돌 연출을 검토했다.
- 사운드: 외부 음원 없이 WebAudio로 심박·입력·성공·충돌·폭탄 효과음을 합성하는 모듈을 작성했다.
- QA: 200ms 경계, 중복 입력, 점수 정산, 팀전 잠금과 폭탄 공개 시점 등 예외 상황을 검토했다.
- 통합 담당: 실제 사이트 코드, 서버 규칙, 테스트, Git 기록과 배포를 통합했다. 독립 검토 결과를 실제 동작으로 연결하는 책임을 한 곳에 두었다.

### 서버가 입력을 판정하도록 구현
모바일 클라이언트는 입력 의도를 전송하고, Cloudflare Worker와 D1이 방 상태를 관리한다. SQLite의 조건부 UPDATE 한 문장으로 참가 자격, 라운드·입력 번호, 중복 입력, 팀전 연속 제한과 유효 시간을 검사한다.
최초 유효 DB 쓰기 시각을 t0로 두고 t0부터 t0+200ms까지 같은 숫자의 입력을 받는다. 정확히 200ms는 포함하며 201ms는 제외한다. 기기 시각이나 클라이언트가 보내는 시간을 신뢰하지 않는다.
판정 확정과 점수 정산은 버전 비교 갱신으로 한 번만 반영한다. 같은 숫자를 재전송하거나 여러 사람이 동시에 결과를 요청해도 점수를 중복 지급하지 않는다.

### 쿨타임과 동기화
- 다음 숫자로 계속 진행하는 단독 성공 뒤에 500~1500ms 무작위 쿨타임을 설정한다.
- 쿨타임은 앞선 조회 시점이 아닌 실제 저장 시점 기준으로 시작한다.
- 화면에는 남은 쿨타임 숫자나 진행률을 예고하지 않는다.
- 현재 구현은 WebSocket이 아니라 짧은 HTTP 폴링이다. 플레이 중 응답 완료 후 약 140ms, 로비·결과 약 650ms, 백그라운드 약 1200ms 간격으로 동기화한다.
- 결과를 보는 체감 지연에는 200ms 판정 창 외에 네트워크·DB 처리와 폴링 대기가 추가된다.

### 긴장감을 위한 UI·사운드
큰 공통 숫자, 다음 숫자의 보상, 개인 점수와 팀 합계, 하나의 큰 입력 버튼을 중심으로 구성했다. 조작 설명은 접힌 영역으로 두고 플레이 화면에서는 선택에 집중하도록 했다.
충돌·폭탄 이벤트에는 셰이크·붉은 피드백과 효과음을 연결했다. 폭탄 없는 결과를 공개할 때는 폭탄 효과를 내지 않는다. 음소거와 동작 줄이기 설정을 지원한다.

### 데이터와 접속
방은 2시간 유효하며, 개인 재접속 토큰은 탭의 sessionStorage에 저장한다. 서버에는 토큰 해시를 저장하고 공개 응답에서는 폭탄 비밀값·타인 힌트·자격 정보를 제거한다.
DB는 death_rooms 테이블의 룸별 JSON 상태를 사용한다. 테이블과 컬럼 description을 스키마·문서에 기록했으며, 팀 수·점수·폭탄 없음은 기존 JSON 구조를 확장해 추가 테이블 없이 처리했다. 폭탄 숫자 0은 서버 내부에서 ‘폭탄 없음’을 뜻하고 UI는 ‘없음’으로 표시한다.

## 5. 검증과 확인 범위
### 자동 규칙 검증
현재 27개 규칙·API 테스트를 통과했다. 주요 검증은 다음과 같다.
- 15개 독립 참가 입력의 충돌, 정확한 200ms 경계와 201ms 거절.
- 동일 참가자 중복 입력, 잘못된 토큰, 지난 라운드·입력 번호 거절.
- 점수 중복 지급 방지, 숫자별 증가 보상, 3라운드 최종 개인·팀 순위.
- 팀전 두 번 연속 성공 뒤 차단 및 다른 참가자의 성공 후 해제.
- 2팀·3팀 전환, 자유 팀 편성, 방장 권한, 시작 후 팀 변경 차단.
- 1~15 모든 폭탄 위치에서 즉시 종료와 다음 입력 거절.
- 폭탄 없는 라운드의 비공개 정보, 15까지 완료했을 때 총 지급 점수 1,200점 유지, 충돌 시 기존 점수 유지.
- 데이터 저장 지연이 있어도 500~1500ms 쿨타임 유지.

### 실제 HTTP·배포 확인
15명의 실제 사람이 모인 현장 테스트가 아니라, 15개 독립 참가 자격을 생성한 HTTP 통합 테스트를 수행했다. 공개 사이트에서 로그인 없이 입장, 팀전 플레이, 폭탄 종료·누적 0점·추가 입력 거절을 확인했다.
빌드와 타입 검사, 배포 성공 상태를 확인했다. AI 결과물 페이지에서는 데스 카운트 카드와 직접 플레이 링크, 기존 워드링크 및 다른 결과물의 보존을 확인했다.
폭탄 없는 라운드의 끝까지 진행·점수 보존은 결정적 자동 테스트로 검증했다. 확률 20%의 재미·체감 빈도와 15인 현장 네트워크 품질은 별도 사용자 테스트로 평가해야 한다.

## 6. 현재 범위와 남은 확인 사항
- 5~10분은 초기 목표 플레이 시간이며 실제 사용자 평균으로 측정한 값이 아니다. 입력 제한 시간이 없어 참가자가 모두 기다리면 더 길어질 수 있다.
- 모바일 웹으로 공개했으며 별도 네이티브 앱 배포를 완료한 것은 아니다.
- 개인전의 적극적 반복 클릭과 자유 팀 인원 차이가 승률에 주는 영향, 폭탄 없음 힌트의 강도는 플레이테스트 대상이다.
- 실제 15명이 서로 다른 네트워크에서 접속했을 때의 지연과 동시 입력 체감 공정성은 추가 확인이 필요하다.
- 진행 중 참가자 교체와 방장 자동 위임은 제공하지 않는다. 같은 탭 새로고침으로 참가 정보를 복구할 수 있다.
